Context keys (both call sites supply the first block; the standalone view adds the last three): entry_rows list of {entry, label} for the table below can_admin the caller manages this ACL can_share the caller may create an ACL entry at some level is_owner the caller owns the sharing scope is_personal a Personal workspace: one holder, never shareable is_workspace_resource this resource *is* a workspace, not something inside one - several switches below only make sense there no_takeover takeover is forbidden here (or on an ancestor) can_take_over the caller is a superuser who may take over publish_titles workspace allows titles to be published to non-readers can_publish_titles ...and the caller may change that access_url where grant/revoke forms post search {query, users:[{id,label}], groups:[{id,label}], truncated} Standalone only: standalone, permissions, effects, subject_types, owner_rows, max_grantable. The split matters. Inline, this renders the table and a link. The forms used to render on every workspace and project page, stacked under the content - and two of them (workspace kind, title publication) silently acted on the *workspace* while sitting on a *project* page, which is how the interface ended up looking like it was doing something random. {% endcomment %}
